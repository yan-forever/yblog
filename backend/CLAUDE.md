## 项目概述
这是一个基于 **Drogon C++ Web框架** 的博客系统后端，提供帖子（Articles）的 RESTful API 服务。

## 技术栈
- **框架**: Drogon (C++ Web Framework)
- **语言**: C++17
- **数据库**: mariadb
- **构建系统**: CMake
- **依赖管理**: vcpkg

## 代码架构

### 目录结构
```
backend/
├── main.cc                          # 应用入口，加载配置并启动服务器
├── config.yaml                      # 服务配置文件
├── CMakeLists.txt                   # CMake 构建配置
├── xmake.lua                        # xmake 构建配置（已废弃）
├── controllers/                     # HTTP 控制器处理 API 请求
│   ├── api_v1_Articles.h           # 文章 API 控制器头文件（自动生成）
│   └── api_v1_Articles.cc          # 文章 API 控制器实现
├── models/                          # 数据库模型（ORM）（自动生成）
│   ├── Article.h                   # Article 模型（自动生成）
│   └── Article.cc                  # Article 模型实现（自动生成）
└── dto/                             # Data Transfer Objects
    ├── Articlesdto.h               # 文章相关 DTO
    ├── CommonResponse.h            # 统一响应封装
    └── utils.h
```

### 架构说明
1. **入口层 (main.cc)**: 加载配置文件，注册 CORS 中间件，启动 HTTP 服务器
2. **控制器层 (controllers/)**: 处理 HTTP 请求，调用模型层，返回响应
   - 继承自 `drogon::HttpController`
   - RESTful 接口：GET / POST / PUT / DELETE
3. **模型层 (models/)**: Drogon ORM 自动生成，提供数据库表与 C++ 对象的映射
   - 所有修改必须使用 `./drogon` 重新生成
4. **DTO 层 (dto/)**: 定义请求/响应的数据结构，使用 nlohmann/json 序列化

## 数据库操作

### 自动生成模型
使用目录下的 `drogon.sh` 从数据库表生成模型：

```bash
# 格式
./drogon create model <json_config_file>

# 示例
./drogon create model models/model.json
```

**配置示例** (`models/model.json`):

```json
{
  "rdbms": "mysql",
  "host": "127.0.0.1",
  "port": 3306,
  "dbname": "yblog",
  "user": "root",
  "password": "publicclass",
  "tables": [],
  "restful": false
}
```

**关键说明：**
- `tables`: 为空数组 `[]` 表示生成数据库中**所有表**的模型
- 如果只想生成特定表，可以指定表名： `"tables": ["article", "category"]`
- 模型文件生成在 `models/` 目录下，每个表对应 `.h` 和 `.cc` 文件

#### 更新数据库后重新生成模型

当你修改数据库 schema（添加/删除表或字段）后，需要重新生成模型：

```bash
# 1. 确保数据库已更新（通过 Atlas 或直接 SQL）

# 2. 从 backend 目录执行（关键！）
cd /root/lib/yblog/backend

# 3. 重新生成所有模型
./drogon.sh create model models

# 4. 输入 y 确认覆盖现有文件
# 程序会显示：Source files in the models folder will be overwritten, continue(y/n)?
# 输入 y
```

**⚠️ 重要提示：**
- 模型文件由 `drogon_ctl` 自动生成，**不要手动编辑**
- 文件顶部注释明确写着：`DO NOT EDIT. This file is generated by drogon_ctl`
- 每次数据库结构变更后，都必须重新生成模型
- 重新生成会覆盖所有更改，所以：**不要在模型文件中添加自定义代码**
- 自定义逻辑应该写在控制器（controllers/）或服务层中

**常见错误及解决：**

**错误 1：** `Create model No such file or directory : models/model.json`

**原因：** drogon_ctl 无法找到配置文件

**解决方案：**
- 确保在 `backend` 目录下执行（不能在其他目录）
- 使用绝对路径或正确的相对路径
- 推荐：`./drogon.sh create model models`

**错误 2：** `mysql Connect to server... Abort!`

**原因：** 数据库连接失败

**解决方案：**
- 检查 `models/model.json` 中的数据库配置是否正确
- 确保 MySQL/MariaDB 服务正在运行
- 检查用户名、密码、主机地址和端口

**错误 3：** 生成的文件没有包含新添加的表或字段

**原因：** 数据库 schema 未更新或缓存问题

**解决方案：**
- 确认数据库已成功应用 schema 变更
- 检查数据库中表和字段已存在：
  ```bash
  mysql -u root -p yblog -e "SHOW TABLES; DESCRIBE article;"
  ```
- 尝试删除旧的模型文件后重新生成：
  ```bash
  rm models/Article.* models/Category.* models/Tag.* models/Article_tag.*
  ./drogon.sh create model models
  ```

**工作原理：**
`drogon.sh` 是一个包装脚本，它会：
1. 查找 vcpkg 安装的 `drogon_ctl` 工具
2. 使用 `drogon_ctl` 连接数据库
3. 读取数据库表结构
4. 根据模板生成对应的 C++ 模型类（.h 和 .cc 文件）

生成的模型类继承自 Drogon ORM 框架，提供：
- 数据库字段到 C++ 成员的映射
- CRUD 操作方法（create, update, delete, findById 等）
- JSON 序列化/反序列化
- 异步数据库操作支持

### MySQL 配置 (config.yaml)
> **重要说明**：虽然配置中写的是 `rdbms: mysql`，但实际上对接的是 **MariaDB** 数据库。Drogon 框架为了兼容性考虑，统一使用 "mysql" 作为配置名称，但其数据库驱动同时兼容 MySQL 和 MariaDB。

```yaml
db_clients:
  - name: default
    rdbms: mysql  # 实际使用的是 MariaDB，mysql 仅为兼容配置
    host: 127.0.0.1
    port: 3306
    dbname: yblog
    user: root
    passwd: publicclass
    number_of_connections: 5
```

### 数据库 Schema 管理

项目使用 **Atlas** 工具管理数据库 schema（`schema.hcl` 文件）。

#### Schema 文件
- **位置**: `/root/lib/yblog/backend/schema.hcl`
- **作用**: 定义数据库表结构、字段、索引等
- **格式**: HCL (HashiCorp Configuration Language)

#### 应用 Schema 更改

当修改 `schema.hcl` 文件后，需要执行以下命令应用更改：

```bash
# 应用 schema 更改到 local 环境
atlas schema apply --env local --auto-approve
```

**命令说明：**
- `atlas schema apply`: 使用 Atlas 工具应用 schema 更改
- `--env local`: 指定环境为 local（使用 atlas.hcl 中 local 环境的配置）
- `--auto-approve`: 自动确认应用更改，无需交互式确认

#### 工作流程

1. **修改 schema**：编辑 `schema.hcl` 文件
2. **应用更改**：运行 `atlas schema apply --env local --auto-approve`
3. **更新模型**：运行 `./drogon create model models/model.json` 重新生成 C++ 模型
4. **更新代码**：修改 DTO 和控制器逻辑（如有必要）

#### 示例：添加新字段

```hcl
# 在 schema.hcl 中添加新字段
table "article" {
  schema = schema.yblog
  // 现有字段...

  # 添加新字段
  column "status" {
    null = false
    type = varchar(20)
    default = "draft"
  }
}
```

然后执行：
```bash
# 1. 应用 schema 更改
atlas schema apply --env local --auto-approve

# 2. 重新生成模型
./drogon.sh create model models/model.json

# 3. 更新 DTO（如果需要）
# 编辑 dto/Articlesdto.h
```

#### 注意事项

- 执行 `schema apply` 前请确保数据库连接正常
- 对于生产环境，建议先使用 `schema diff` 查看将要执行的更改：
  ```bash
  schema diff --env local
  ```
- 重要表的修改建议先备份数据
- 如果模型生成失败，检查 schema 是否已成功应用到数据库

## API 开发规范

### 异步 API 规范

根据 drogon.wiki 文档，所有控制器处理函数必须使用异步接口：

#### 标准函数签名
```c++
void handlerName(
    const HttpRequestPtr &req,
    std::function<void(const HttpResponsePtr &)> &&callback,
    ...  // 参数列表
);
```

**关键规则：**
1. **强制使用异步回调**：所有处理函数必须接收 `std::function<void(const HttpResponsePtr &)> &&callback` 参数
2. **不要阻塞 IO 线程**：耗时操作（数据库查询、外部 API 调用等）必须在其他线程执行
3. **通过 callback 返回响应**：生成 HttpResponsePtr 后，必须通过 `callback(resp)` 返回
4. **回调只能调用一次**：每个请求对应的 callback 只能被调用一次，否则会导致未定义行为

#### 异步处理示例
```c++
void User::getInfo(
    const HttpRequestPtr &req,
    std::function<void(const HttpResponsePtr &)> &&callback,
    std::string userId,
    const std::string &token) const
{
    // 日志记录（快速操作，可在 IO 线程执行）
    LOG_DEBUG << "User " << userId << " get his information";

    // 耗时操作：数据库查询（必须在其他线程执行）
    auto dbClient = drogon::app().getDbClient();
    dbClient->execSqlAsync(
        "SELECT * FROM users WHERE id=?",
        [callback = std::move(callback)](const drogon::orm::Result &result) {
            // 在回调中生成响应并返回
            Json::Value ret;
            if (result.size() > 0) {
                ret["result"] = "ok";
                ret["user_name"] = result[0]["name"].as<std::string>();
            } else {
                ret["result"] = "error";
                ret["message"] = "User not found";
            }
            auto resp = HttpResponse::newHttpJsonResponse(ret);
            callback(resp);
        },
        [callback = std::move(callback)](const drogon::orm::DrogonDbException &e) {
            // 错误处理
            Json::Value ret;
            ret["result"] = "error";
            ret["message"] = e.base().what();
            auto resp = HttpResponse::newHttpJsonResponse(ret);
            callback(resp);
        },
        userId
    );
}
```

### RESTful API 规范

根据 drogon.wiki 文档，RESTful API 应遵循以下规则：

#### 1. 使用 HttpController（而非 HttpSimpleController）
- **HttpController**：一个类可定义多个处理函数，支持 RESTful 风格
- **HttpSimpleController**：每个类只能定义一个处理函数，不适合 RESTful API

#### 2. HTTP Method 语义
在同一个 URL 路径上使用不同的 HTTP Method 表示不同操作：

```c++
class ArticleController : public drogon::HttpController<ArticleController>
{
public:
    METHOD_LIST_BEGIN
        // GET /api/v1/articles - 获取文章列表
        METHOD_ADD(ArticleController::getList, "/api/v1/articles", Get);

        // POST /api/v1/articles - 创建新文章
        METHOD_ADD(ArticleController::create, "/api/v1/articles", Post);

        // GET /api/v1/articles/{id} - 获取单个文章
        METHOD_ADD(ArticleController::getOne, "/api/v1/articles/{1}", Get);

        // PUT /api/v1/articles/{id} - 更新文章
        METHOD_ADD(ArticleController::update, "/api/v1/articles/{1}", Put);

        // DELETE /api/v1/articles/{id} - 删除文章
        METHOD_ADD(ArticleController::deleteOne, "/api/v1/articles/{1}", Delete);
    METHOD_LIST_END
};
```

#### 3. HTTP Method 标准语义
| Method | 操作 | 幂等性 | 示例 |
|--------|------|--------|------|
| GET | 查询资源 | 是 | GET /articles, GET /articles/{id} |
| POST | 创建资源 | 否 | POST /articles |
| PUT | 替换资源 | 是 | PUT /articles/{id} |
| PATCH | 部分更新资源 | 否 | PATCH /articles/{id} |
| DELETE | 删除资源 | 是 | DELETE /articles/{id} |

#### 4. URL 路径设计规范

**规则 1：使用复数名词表示资源集合**
```c++
// 正确
"/api/v1/articles"
"/api/v1/users"
"/api/v1/comments"

// 错误
"/api/v1/article"
"/api/v1/getArticles"
```

**规则 2：使用层级关系表示资源关联**
```c++
// 获取文章的所有评论
"/api/v1/articles/{article_id}/comments"

// 获取用户的文章
"/api/v1/users/{user_id}/articles"
```

**规则 3：路径参数映射**
```c++
// 推荐写法：提高可读性
METHOD_ADD(getInfo, "/{user_id}", Get);
METHOD_ADD(getInfo, "/{1:user_id}", Get);

// 等价的其他写法
METHOD_ADD(getInfo, "/{}", Get);
METHOD_ADD(getInfo, "/{1}", Get);
```

#### 5. 请求参数处理

**GET 请求**：查询参数放在 URL（如 `?key=value`）
```c++
// GET /api/v1/articles?page=1&limit=10
METHOD_ADD(getList, "/api/v1/articles?page={1}&limit={2}", Get);
void getList(const HttpRequestPtr &req,
             std::function<void(const HttpResponsePtr &)> &&callback,
             int page, int limit);
```

**POST/PUT/PATCH 请求**：数据放在请求体（Body）
```c++
// POST /api/v1/articles
// Body: { "title": "xxx", "content": "yyy" }
METHOD_ADD(create, "/api/v1/articles", Post);
void create(const HttpRequestPtr &req,
            std::function<void(const HttpResponsePtr &)> &&callback);
```

#### 6. 参数映射类型支持
处理函数参数可以使用以下类型：
- 基础类型：`int`, `long`, `long long`, `unsigned long`, `unsigned long long`, `float`, `double`
- 字符串：`std::string`
- 自定义类型：任何可以使用 `stringstream >>` 操作符赋值的类型
- JSON 对象：通过特化 `drogon::fromRequest` 模板实现自动转换

#### 7. 响应格式

**成功响应**：统一使用 JSON 格式
```c++
// 查询成功
{
    "result": "ok",
    "data": { /* 资源数据 */ }
}

// 列表查询
{
    "result": "ok",
    "data": [ /* 资源数组 */ ],
    "total": 100,  // 可选：总记录数
    "page": 1      // 可选：当前页码
}
```

**错误响应**：统一格式
```c++
{
    "result": "error",
    "message": "错误描述信息"
}
```

**HTTP 状态码映射**：
- 200 OK: 查询成功、更新成功
- 201 Created: 创建成功（返回新资源）
- 204 No Content: 删除成功
- 400 Bad Request: 请求参数错误
- 401 Unauthorized: 未认证
- 403 Forbidden: 权限不足
- 404 Not Found: 资源不存在
- 500 Internal Server Error: 服务器错误

#### 8. RESTful API 设计示例

```c++
class ArticleController : public drogon::HttpController<ArticleController>
{
public:
    METHOD_LIST_BEGIN
        // 集合操作
        METHOD_ADD(getList, "/api/v1/articles?offset={1}&limit={2}", Get);    // 获取列表
        METHOD_ADD(create, "/api/v1/articles", Post);                        // 创建资源

        // 单个资源操作
        METHOD_ADD(getOne, "/api/v1/articles/{1}", Get);                    // 获取单个
        METHOD_ADD(update, "/api/v1/articles/{1}", Put);                    // 完整更新
        METHOD_ADD(patch, "/api/v1/articles/{1}", Patch);                   // 部分更新
        METHOD_ADD(deleteOne, "/api/v1/articles/{1}", Delete);              // 删除
    METHOD_LIST_END

private:
    void getList(const HttpRequestPtr &req,
                 std::function<void(const HttpResponsePtr &)> &&callback,
                 size_t offset, size_t limit);

    void create(const HttpRequestPtr &req,
                std::function<void(const HttpResponsePtr &)> &&callback);

    void getOne(const HttpRequestPtr &req,
                std::function<void(const HttpResponsePtr &)> &&callback,
                int articleId);

    void update(const HttpRequestPtr &req,
                std::function<void(const HttpResponsePtr &)> &&callback,
                int articleId);

    void patch(const HttpRequestPtr &req,
               std::function<void(const HttpResponsePtr &)> &&callback,
               int articleId);

    void deleteOne(const HttpRequestPtr &req,
                   std::function<void(const HttpResponsePtr &)> &&callback,
                   int articleId);
};
```

## Git 提交规范

### Conventional Commits（约定式提交）

本项目使用 **Conventional Commits** 规范来标准化 Git 提交信息，结合 `git cz` 工具简化提交流程。

#### 提交格式

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

#### 类型 (Type)

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: 添加用户登录 API` |
| `fix` | 修复 Bug | `fix: 修复文章删除时的空指针异常` |
| `docs` | 文档更新 | `docs: 更新 API 文档` |
| `style` | 代码格式调整 | `style: 格式化 Article.cc` |
| `refactor` | 代码重构 | `refactor: 重构 ArticleController` |
| `test` | 添加测试 | `test: 添加 Article 模型测试` |
| `chore` | 构建过程或辅助工具的变动 | `chore: 更新依赖版本` |
| `perf` | 性能优化 | `perf: 优化数据库查询性能` |
| `ci` | CI 配置变动 | `ci: 更新 GitHub Actions 配置` |

2. **自动生成 Changelog**：可以基于提交记录自动生成版本日志
3. **语义化版本**：根据提交类型自动判断版本号变更（feat=次版本号，fix=修订号）
4. **团队协作**：新成员可以快速了解项目规范和提交历史
5. **工具集成**：与 CI/CD、版本发布工具无缝集成

## 配置文件 (config.yaml)
- **监听端口**: 8080
- **静态文件**: ./static
- **上传目录**: uploads
- **DB**: 见上述 MySQL 配置
- **JSON**: jsoncpp 解析
- **GZIP/Brotli**: 压缩启用
- **Session**: 启用（设置 cookie）
